# EvalPilot 模拟评委盲审

Date: 2026-09-13

Scope: 公开产品站、B 站视频、GitHub Release、评分证据索引和提交文案。评审只依据仓库中可追溯的实测材料。

## 综合结论

- 保守区间：`93-95 / 100`
- 最可能结果：`94 / 100`
- 高校组前三判断：有竞争力，但并非仅靠功能数量锁定；关键在提交材料是否让评委在 3 分钟内看懂差异化，以及市场证据是否被诚实表达。
- 最大风险：市场可行性只有“预算品类、公开采用信号、集成路径和成本”，没有真实付费客户、付费试点或外部采用转化。

## 分项盲审

### 技术可行性：20 / 20

已经呈现：

- 可运行 FastAPI + React + SQLite 产品。
- 一条命令启动。
- 外部 HTTP SUT，不是只对内部 mock 评测。
- 公开 Haystack 3.0.0 / 3.1.1 比较，52 次、0 个语义差异。
- 8 次 HTTP 反事实重放。
- 缓存离线一致复现；无缓存且 SUT 故障时明确失败。
- 后端 388 passed / 1 skipped；前端 153 passed；类型检查和生产构建通过。

评委可能追问：

- “这是不是只在一台机器上能跑？” 回答：已在独立 clean worktree 完成依赖安装与 31/31 E2E，但尚未验证第二台物理机，不能夸大为生产部署。
- “SUT 是不是自己造的？” 回答：SUT 是真实公开 Haystack pipeline 的 HTTP 适配层，candidate patch 是受控应用层变更；不冒称上游本身存在缺陷。

### 市场可行性：17-18 / 20

已经呈现：

- LLM 评测与质量运营已有公开付费品类。
- Langfuse、Promptfoo、DeepEval 等项目有公开采用信号。
- 产品定位不是另一个 dashboard，而是 CI/CD 发布质量门禁。
- CI 退出码 `0/1/2`、JUnit、SARIF、Webhook、PR 回写已实现。
- 一次完整 Live Run 的成本已测量。
- 有固定交付、团队订阅和企业自托管三种商业模式假设。

扣分原因：

- 没有付费客户、paid pilot、外部安装量或真实转换数据。
- `$0.264697` 是已记录场景和价格假设下的运行下界，不是通用价格。
- 目前是“发布门禁”切口，但还需要证明它能在客户已有工具链中低摩擦替换或并接。

结论：不能解决短期商业验证，但可以通过不虚构、不夸大，保住诚实和可执行性分数。

### 综合创新性：18-19 / 20

已经呈现：

- 匹配场景 + 控制组 + 配对区间区分版本变化与噪声。
- Naive delta 与 EvalPilot 结论的公开对照。
- 反事实重放确认具体干预是否恢复失败。
- 历史事故可再生为后续回归记忆。

评委可能追问：

- “这是算法创新还是工程整合？” 回答：核心创新在于把统计比较、可执行反事实和发布门禁组合成端到端决策闭环；不宣称发明新的统计算法。
- “模型规划是不是装饰？” 回答：模型在 OOD 规划 6/6，并可改变下一步实验；但仍需通过白名单校验，由引擎执行和测量。

### AI 大模型结合：19 / 20

已经呈现：

- DeepSeek V4 Pro 用于风险假设、受约束规划、Judge 和报告解释。
- 模型规划 8/8；确定性规则同样 8/8，所以不把模型写成唯一实现。
- 1 个 persisted model-guided replay plan 进入真实执行链。
- 52 次 Judge 调用、78,695 tokens、token 和调用预算均有记录。
- 模型不能覆盖分数、证据、根因和发布决策。

扣分原因：尚未提供第二模型供应商对照；真实人工 Judge 标签仍需外部提供。

### 赛道维度：19 / 20

已经呈现：

- 自然语言目标 -> 规划 -> 工具 -> 证据 -> 调查 -> 重放 -> 发布决策。
- 报告、退出码、PR 回写和回归记忆构成可验收交付。
- 2:28.97 中文演示视频，1080p，展示模型规划面板。
- 公开产品站提供无需安装的入口。

扣分原因：浏览器执行、多租户和生产权限仍属于路线图，不能写入“已实现”。

## 评审会问的五个问题

1. **为什么不是现有 observability / eval 工具的一部分？**
   EvalPilot 不替代追踪平台，而是消费版本对比结果，交付一个可阻断发布的 release gate。

2. **为什么必须用 Agent，而不是固定脚本？**
   固定规则在已知故障上同样有效；模型的价值在于为模糊版本描述生成风险假设和 OOD 实验，但所有实验都受白名单约束。

3. **如何避免 LLM 把错误结论说成真的？**
   模型只解释和规划，分数、证据、反事实恢复、风险级别与 BLOCK/REVIEW/ALLOW 由确定性引擎掌握。

4. **26 个场景会不会太小？**
   报告包含最小可检测效应、所需样本数、观察功效和样本充足性；小样本会明确提示区间可能不充分，局部硬失败仍可阻断。

5. **商业模式有验证吗？**
   目前验证的是品类预算、公开采用、集成方式和成本，不是客户采购。不能声称付费验证。

## P0 结论

- 技术、Agent 和赛道材料已达到可提交状态。
- 提交时最重要的是让“发布质量门禁”这四个字在首屏出现，并让评委 1 次点击看到 8/26、52/0、4/4 和视频。
- 不应在初赛前新增浏览器执行、SSO、多租户等功能来稀释已经完成的闭环。
- 最大增分机会在 P1：公开未知故障应用回顾性诊断或真实外部采用信号。
